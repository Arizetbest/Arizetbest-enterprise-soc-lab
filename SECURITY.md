# Security Policy

## Supported versions

Security fixes are applied to the latest release on the `main` branch.

## Reporting a vulnerability

Do not open a public issue containing credentials, personal data, production logs, internal hostnames, or exploitable environment details. Use GitHub's private vulnerability reporting feature when available, or contact the repository owner privately through the contact method on the GitHub profile.

Include:

- affected version or commit;
- a clear description of the issue;
- safe reproduction steps using synthetic data;
- potential impact; and
- a suggested remediation, if known.

## Data handling

Contributors must use synthetic or sanitized evidence. Examples use documentation-only IP ranges and non-production identities. Never commit secrets, tokens, passwords, private keys, raw Security event logs, or identifiable customer information.

## Authorized use

The toolkit is for defensive administration, SOC investigation, and education on systems the operator owns or is explicitly authorized to assess.
